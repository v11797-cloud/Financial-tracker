# 협회 제·개정 요약 연결

협회규정·모범규준 상세는 `kofia_summaries.json`을 읽는다. 국가법령정보센터의 `law_reasons.js`와 분리했다. 피드 ID, 게시일, 확인 기록, Workspace 저장 키는 바꾸지 않는다.

`collect_kofia_summaries.py`는 협회 상세 페이지에서 규정명·제개정일과 전문 링크의 규정번호·이력번호를 모두 확인한다. 요약문을 우선 읽고, 비어 있으면 그 상세에 연결된 개정문(HWP 5/HWPX)의 텍스트를 추출한다. PDF 등 미지원 첨부나 첨부 읽기 실패 시 검증한 해당 이력의 전문을 발췌하며, 화면에 변경사항 요약과 다름을 명시한다. 원문이 제공하지 않은 변경사항은 만들지 않는다.

HWP 처리는 [한컴의 본문 파싱 설명](https://tech.hancom.com/python-hwp-parsing-2/) 및 [HWPX 구조 설명](https://tech.hancom.com/hwpxformat/)을 참고한다. 파일을 실행하지 않으며, 보호된 HWP·손상 레코드·과도한 압축 해제·외부 XML 선언을 거부한다. URL은 협회 HTTPS의 고정 경로와 숫자 식별자로 제한하고 리다이렉트를 따라가지 않는다.

원문 요약/첨부 발췌/해당 시점 전문을 구분한다. 수집 대기, 미제공, 일시 실패도 구분한다. 한 번에 180건, 동시 3건, 기본 300초를 한도로 새 자료부터 수집하고 이전의 검증된 일치 자료는 보존한다. 연속 실패 6건이면 서버에 재요청을 계속하지 않는다. 회차별 결과 건수는 JSON `counts`와 실행 로그에서 확인한다. 전체 안건에 대한 요약 완성을 뜻하지 않는다.

`UI 2.0 KOFIA Revision Summaries` 워크플로가 기존 협회 데이터 워크플로 성공 후 실행되어 새 개정 건도 자동으로 연결한다. 초기에는 과거에 보관한 공식 HTML을 다시 대조한 1건을 포함하며, 다른 건은 실제 수집 전까지 대기로 표시한다. 실시간 사이트 응답이 없는데 최신 원문을 읽었다고 표시하지 않는다.

검증: Python 원문 동일성·첨부 추출·HWP 제어문자·오류·캐시 보존 검사, 브라우저 협회규정/모범규준·출처 구분·식별자 불일치·안전하지 않은 링크·수집 상태·모바일·문자열 XSS 검사.
