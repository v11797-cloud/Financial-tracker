# Gemini Enterprise 결과 가져오기 — 구현 및 검증

## 1. 변경 파일

- `gemini-analysis.js`: 파싱·검증, 규제 ID 대조, 분석/개인 의견 저장, 이력, JSON 합치기, 통합 백업 복원 트랜잭션.
- `gemini-analysis-ui.js`, `gemini-analysis.css`: 규제별 검토 노트, 붙여넣기/미리보기/저장, 이력·삭제·복사·내보내기, 보관함.
- `gemini-enterprise.js`: 기존 Handoff 재사용, 규제 ID와 Export 블록 지시 추가, 가져오기 버튼 연결.
- `workspace.js`, `workspace-format.js`: 연결 규제에 검토 노트 표시, 체크리스트 전환, 분석을 포함하는 백업·이전 백업 호환.
- `app.js`, `ai-ui.js`, `index.html`: 우선검토/상세/Workspace 연결과 상대경로 스크립트 로딩.
- `guide.html`: 사용자 흐름 및 저장 안내.
- `tests/gemini-analysis.test.cjs`, `tests/gemini-import-browser.cjs`: 신규 검증.
- `tests/ai-browser.cjs`: 우선검토에 Gemini 버튼이 생긴 최종 UI에 맞춘 기존 검증 갱신.
- `.github/workflows/ui-v2-kofia.yml`: 기존 검사 단계에 Gemini 단위 테스트 추가.

수집기나 운영 데이터는 이번 기능 때문에 변경하지 않았다. 기존 미커밋 작업은 보존했다.

## 2. 현재 Workspace와 연결

현재 Workspace는 여러 규제를 상단/본문에 연결할 수 있는 자유 메모 구조다. 이 구조를 유지하면서 연결된 규제마다 강조된 `① Gemini로 분석하기`와 `② 결과 가져오기`를 바로 표시한다. `내 의견 작성`은 개인 검토용이며 Gemini 시작을 위해 거치지 않아도 된다. 저장한 분석이 있으면 `① Gemini로 다시 분석` 및 `분석 보기`를 제공한다. 규제별 개인 의견과 검토 상태는 stable regulation ID로 관리한다. 같은 규제가 제목 변경 후 수집돼도 ID가 같으면 기존 분석·개인 의견을 조회한다.

우선검토 추천만으로 Workspace를 채우지 않는다. 메모 연결은 직접 선택할 때 등록하며, 심층분석 실행만으로 새 Workspace 노트를 만들지 않는다. 결과 저장 시 Workspace 미등록 안건은 추가 확인 후 연결한다. 우선검토 제외, 규제 링크 삭제, Workspace 비우기는 저장된 분석을 삭제하지 않는다. `Gemini 분석 보관함`에서 다시 조회할 수 있다.

## 3. 가져오기 기능

1. 우선검토 또는 규제 상세에서 **Gemini Enterprise 심층분석** 클릭.
2. 프롬프트를 Gemini에 붙여넣고 사용자가 분석 실행.
3. Gemini 답변 전체 복사.
4. RegWatch의 **분석 결과 가져오기** → 붙여넣기 → **미리보기**.
5. 연결 규제와 분석을 확인하고 **분석 결과 저장**.

미리보기/취소만으로 분석이나 개인 의견을 덮어쓰지 않는다. 저장 실패 시 입력을 남기며, 붙여넣은 원문을 파일로 내보낼 수 있다. 붙여넣기 창을 닫아도 같은 페이지 세션의 입력 초안은 다시 열 때 유지된다. 클립보드를 자동으로 읽지 않는다.

## 4. 프롬프트 변경

기존 실무 심층분석 지시사항과 Agent URL 설정을 유지했다. 공개 규제 ID·제목·기관/부서·일정·URL·상세내용·업무 관점만 allowlist로 프롬프트에 넣는다. 개인 메모·개인 의견·저장된 분석은 포함하지 않는다.

답변 마지막에 `[REGWATCH_EXPORT_V1]` / `[/REGWATCH_EXPORT_V1]` 안에 schema_version 1 JSON을 출력하도록 지시한다. 규제 ID 임의 생성, 미확인 변경사항 확정, 가짜 출처·기한 생성을 금지하며 부족한 정보는 빈 배열/추가 확인 필요로 표시하도록 요청한다.

가져오기는 저장 데이터 검증과 별도로 형식 차이를 정규화한다. 문자열 버전 `"1"`, 명시적 camelCase 필드, 추가 메타데이터, 보고서 안의 JSON 코드블록, `analysis` / `result` / `structuredResult` 객체를 지원한다. 빠진 필드는 빈 값으로 두고, 목록 필드에 단일 텍스트가 있으면 내용 그대로 한 항목으로 읽으며 변경 사항을 미리보기에 알린다. 원문은 항상 전부 보존한다. 지원하지 않는 버전·객체형 목록·잘못된 URL·JSON 문법은 구체적인 오류와 함께 텍스트로 남긴다. 충돌하는 규제 ID나 여러 분석 블록은 저장을 차단한다. 기존 저장 데이터·백업의 V1 검증은 그대로 엄격하게 유지한다.

확인된 Enterprise 대체 출력은 `title`을 제목으로, `department_impacts`의 부서·영향도·근거를 업무 영향으로, `action_items`의 우선순위·Action·부서·시점을 검토사항으로 변환한다. `checklist_questions`도 검토사항에 포함한다. 이 명시적 객체 형식 외의 임의 객체는 자동 해석하지 않는다. 규제 ID가 비어 있으면 추정하지 않고 선택 안건에 저장한다는 별도 확인을 받는다. 날짜·내규 영향·시스템 영향·교육 정보 등 추가 필드는 원문에 보관하며 규제 Feed 메타데이터를 변경하지 않는다. 새로운 Prompt에는 V1 필드 이름과 문자열 배열 사용을 명시한다.

가져오기 호환성 수정 검증: 단위 테스트 84개 중 83개 통과, 기존 날짜 스냅샷 1개 건너뜀. 브라우저에서 대체 출력의 미리보기·ID 확인·저장·새로고침 복원과 기존 가져오기 23개 시나리오, Floating Agent 20개 시나리오 통과. 테스트 데이터는 격리된 브라우저에서 사용하며 실제 사용자 저장소에 쓰지 않는다.

`regwatch_gemini_handoff_v1` sessionStorage에 요청 대상과 준비 시각만 저장한다. 이 상태는 분석 완료를 뜻하지 않는다. 복사나 팝업이 막히거나 Agent URL이 없으면 기존 프롬프트 미리보기와 수동 복사를 사용한다.

## 5. JSON 및 텍스트 처리

마커 블록, JSON 코드펜스, JSON 자체를 지원한다. 필드 타입·버전·목록·URL을 검증한다. 구조화 결과는 핵심 요약, 주요 변경사항, 예상 업무 영향, 검토 필요사항, 불확실성, 원문 순서로 표시한다. 출처 URL의 실제 존재/접근 여부는 검증하지 않는다.

JSON 누락·파싱 실패·지원하지 않는 필드·안전하지 않은 출처 URL·여러 Export 블록은 일반 텍스트로 보존한다. 일반 텍스트에서 요약이나 업무 영향을 만들어내지 않는다. `rawText`는 붙여넣은 전체 원문을 그대로 보관하며 잘라내지 않는다. HTML/script는 textContent/value로 표시해 실행하지 않는다.

## 6. 규제 ID 대조

사용자가 선택한 규제 ID가 저장 대상이다. 결과의 ID로 다른 노트를 자동 선택하지 않는다. 다른 ID이면 저장을 차단한다. ID 없는 일반 답변/확인 불가 결과는 선택한 규제에 저장한다는 체크박스를 별도로 선택해야 한다. 잘못된 스키마라도 읽을 수 있는 다른 ID가 있으면 차단한다.

## 7. 분석 이력

저장마다 새 analysis ID와 RegWatch의 importedAt을 부여한다. 기존 결과는 덮어쓰지 않는다. importedAt 내림차순으로 최신 결과를 표시하고 같은 시각이면 나중에 저장한 항목을 우선한다. 이전 백업을 합쳐도 더 오래된 분석이 최신으로 바뀌지 않는다. `이전 분석 보기`에서 선택하고 원문 복사·내보내기·확인 후 삭제가 가능하다.

## 8. 개인 메모 보호

분석 레코드와 규제별 reviews(개인 의견/상태)를 별도로 관리한다. 새 분석 저장/삭제는 개인 의견과 자유 메모를 변경하지 않는다. 규제 검토 상태(검토 전/중/완료)는 피드의 확인 완료와 독립적이다. 개인 의견은 자동 저장하며 실패하면 화면에 유지하고 재시도·별도 내보내기를 제공한다. 다른 탭의 변경은 조용히 덮어쓰지 않는다.

## 9. 체크리스트 전환

구조화 결과의 recommended_checks를 **검토사항을 할 일로 추가**를 클릭할 때만 연결 메모의 본문 체크리스트로 추가한다. `analysis ID + 항목 인덱스`로 task ID를 만들고 이미 있는 ID는 건너뛴다. 기존 개인 할 일, 완료 상태, 작성 중 초안은 유지한다. 삭제한 할 일을 다시 추가하는 것은 가능하다.

## 10. 저장/백업

- 기존 `regwatch_workspace_v1`: 자유 메모·연결 규제·본문 체크리스트, 키/버전 유지.
- 신규 `regwatch_gemini_analyses_v1`: `{version:1, analyses:[...], reviews:[...]}`.
- analyses: stable ID, 규제 ID/제목, provider=`gemini_enterprise`, importMethod=`manual_paste`, importedAt, format, 구조화 내용, rawText.
- reviews: regulationId, regulationTitle, userMemo, status.
- importedAt은 가져온 시각이며 Gemini 실제 생성 시각이 아니다. provider는 사용자가 표시한 출처이며 API 검증 값이 아니다.

Workspace JSON 내보내기에 `geminiAnalyses`를 추가했다. 통합 복원은 확인 후 Workspace와 분석을 함께 교체하며, 중간 저장 실패 시 이전 저장값으로 복구한다. 기존 형식 백업은 분석 키를 유지한다. 분석 보관함의 JSON 가져오기는 ID로 중복을 제거하고 기존 개인 의견을 보존하며 합친다. 같은 analysis ID의 내용이 다르면 충돌을 알려 덮어쓰지 않는다.

quota/저장소 접근 실패/잘못된 저장값을 처리하며 기존 손상 데이터는 복구용으로 내보낼 수 있다. 붙여넣은 HTML이나 JavaScript는 실행되지 않는다. 붙여넣기와 저장에서 외부 요청이 발생하지 않는다.

## 11. 검증 결과

- Node 단위 테스트: **75개 중 74개 통과, 기존 날짜 스냅샷 1개 건너뜀**.
- 신규 가져오기 브라우저 테스트: 요구한 23개 시나리오에 대응하는 Handoff mock, ID/미리보기/확인/취소, 구조화/텍스트/잘못된 JSON, 이력·재분석, 개인 의견 보호, 체크리스트 중복 방지, XSS, quota 재시도, 백업 호환/복원, 모바일, 경로 및 외부 요청 없음 검증.
- 기존 AI 화면 8개 검증 그룹, 우선검토 15개 시나리오 및 Workspace 생성/편집/서식/규제 삭제/백업 브라우저 검증 통과.
- 실제 Gemini Enterprise 로그인·분석·DOM 조작은 테스트하지 않았다. Agent와 클립보드는 mock으로 검증했다.

## 12. 기존 기능 영향

우선검토에 기존 Gemini Handoff 및 결과 가져오기 버튼을 추가했다. 추천/제외/복원, 피드 검색·필터·업무 관점, 상세 검토 요약, 확인 기록, 기존 Workspace와 Agent URL은 유지한다. 분석만 붙여넣고 취소하면 Workspace에 자동 등록하지 않는다. 미등록 규제는 저장 시 추가 확인 후 연결한다. 심층분석 요청만으로는 노트를 만들지 않는다.

## 13. 배포 방법 및 사용자 확인

현재 수정은 로컬이며 운영 배포하지 않았다. 배포 요청 시 기존 다른 미커밋 변경을 검토해 필요한 파일만 커밋하고 main에 반영한 뒤 기존 `UI 2.0 KOFIA Data` 워크플로를 실행한다. 기존 Pages 산출물에 저장소 루트가 포함되므로 상대경로로 추가한 JS/CSS가 `/Financial-tracker/ui-v2/`에서 함께 배포된다. 성공 후 운영 경로에서 기능과 버전 쿼리를 확인한다.

실제 회사 환경 확인은 다음과 같이 한다: 기존 Agent URL 설정을 유지한 브라우저에서 규제 하나를 선택 → 심층분석 클릭 → 회사 Gemini에서 프롬프트 붙여넣고 실행 → 답변 전체 복사 → RegWatch 가져오기/미리보기 → ID 확인/저장 → 개인 의견 작성 → 새로고침으로 복원 확인. 별도 API 키는 필요하지 않다.

## 14. 남아 있는 제한

자동 양방향 동기화가 아니라 사용자 복사·붙여넣기다. 회사 Agent 접근 권한, 실제 Gemini 답변의 형식 준수 및 분석 정확성은 사용자가 실제 환경에서 확인해야 한다. 저장은 브라우저/사이트 origin별이며 PC 간 동기화되지 않는다. 브라우저 데이터 삭제에 대비한 JSON 백업이 필요하다. 미저장 붙여넣기 초안은 페이지를 떠나면 사라질 수 있으므로 저장 실패 시 원문 내보내기를 사용한다.



현재 플로팅 Agent 사용법과 검증은 [REGWATCH_AGENT_HANDOFF.md](../REGWATCH_AGENT_HANDOFF.md)를 참고한다.


## 원문 본문을 포함한 Gemini 분석 요청

`gemini-source.js`는 상세 화면과 같은 공개 원문 캐시를 읽어 분석 프롬프트에 넣는다. 협회 제·개정은 규정/이력 ID·제목·날짜·분류를 대조하고, 보도자료·예고문은 제목·날짜·공식 주소를, 법령은 법령명·공포번호·날짜를 대조한다. 확인되지 않은 자료나 다른 개정 건으로 대체하지 않는다.

Agent 패널에서 원문 종류와 전달할 글자 수를 확인할 수 있다. 공식 요약, 개정 첨부파일, 규정 전문, 제·개정이유를 구분하고 출처와 수집 시각을 함께 전달한다. 최대 32,000자이며 일부만 포함하면 표시한다. 개인 메모·분석 이력·설정 값은 프롬프트에 넣지 않는다. 수집 대기·확인 실패는 본문 미확보 상태로 안내한다.

분석 실행은 원문 준비를 기다린 뒤 같은 본문을 복사한다. 새 창은 사용자 클릭 시 먼저 확보해 팝업 차단에 대응하며, 복사 실패 시 수동 미리보기를 제공한다. Gemini에서는 새로 복사한 프롬프트를 Ctrl+V → Enter로 실행한다. 외부 원문 링크에 접근할 수 없더라도 제공된 발췌를 분석하고, 빠진 조문이나 시행일만 별도 확인사항으로 표시하도록 요청한다. 원문 미확보 항목은 예비 분석만 가능하다. 회사 Agent의 실제 답변과 권한은 이 사이트에서 확인할 수 없다.

검증: 원문/출처/수집 시각 포함, 잘못된 개정 건 배제, 수집 대기·통신 실패·재시도, 규제 전환 중 응답 순서, 복사 본문 일치, 팝업 순서, 개인 메모 미포함, 데스크톱/모바일 브라우저를 확인한다. 회사 Agent나 모델 API에는 테스트 요청을 보내지 않는다.
